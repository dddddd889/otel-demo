原理课程路线

不建议跳过前两课。自动插桩解决“谁创建 Span”，Context 解决“它为什么能连起来”。

  1. 01自动插桩如何工作对比 baseline、手写 patch 和官方 HTTP instrumentation。

    学完能回答：Instrumentation 何时 patch HTTP 模块，谁创建 Active Span？

  2. 02AsyncLocalStorage 与 OTel Context用并发实验看全局变量串线，再看 Context 如何隔离。

    学完能回答：并发请求为什么不会串 Trace，Context 如何跨 HTTP/MQ？

  3. 03Span Event、LogRecord 与 recordException区分 Span 内部的瞬间事件和独立日志信号。

    学完能回答：Event 存在哪里，recordException() 产生 Event 还是 LogRecord？

  4. 04NodeSDK 的五个核心概念把 Resource、三种信号和 Instrumentation 放回同一条数据流。

    学完能回答：哪些是遥测数据，哪些是来源身份或数据生产者？

始终用这条主线定位数据

业务请求
  → Instrumentation 或手动 API
  → Span / Metric / LogRecord
  → 附加 Resource（service.name 等来源身份）
  → Processor / Reader → Exporter
  → OpenTelemetry Collector
  → Jaeger / Prometheus / Loki

一针见血的排查方法：从最后能看到数据的一层往后查。应用没产生，就查 Instrumentation/API；应用有数据但后端没有，就查 Exporter 和 Collector；后端有数据但查不到，就查 Resource 属性和查询条件。
