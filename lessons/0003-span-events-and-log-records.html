OpenTelemetry 原理课 · 03

Event 住在 Span 里；LogRecord 走独立的 Logs 管道。

用当前项目的异常和关联日志，分清三个容易混淆的词。约 5 分钟。

先看存放关系

Span Event
存在 Span 的 events[]
LogRecord
独立 Logs 信号，可用 Trace ID 关联
recordException
生成名为 exception 的 Span Event

record 不是第四种数据；它只是“记录”这个动作。在 recordException(error) 里，记录结果属于 Trace 信号。

1. Event：Span 时间线上的一个瞬间

span.addEvent('inventory-cache-miss', {
  'demo.cache.system': 'redis',
});

Event 有名称、时间戳和属性，但没有自己的 Span ID，也不是 Span 树的一个节点。它适合表示“这个操作进行到某时发生了什么”。

项目中的 span.recordException(error) 等价于按 OpenTelemetry 异常语义生成一个 exception Event，通常包含 exception.type、exception.message 和 exception.stacktrace。

2. LogRecord：独立的日志记录

logger.emit({
  severityText: 'ERROR',
  body: '支付失败',
  attributes: { 'demo.order.id': orderId },
});

这会生成 LogRecord，包含时间、严重级别、正文、属性，以及当前 Context 中可用的 Trace ID / Span ID。它不存在 Span 的 events[] 中，而是经 Logs SDK 独立导出。

3. 在这个项目里到哪里看

代码数据落点传输与查看
span.addEvent(...)当前 Span 的 events[]OTLP Traces → Collector → Jaeger，打开 Span 看 Events
span.recordException(error)当前 Span 的 exception EventOTLP Traces → Collector → Jaeger，打开失败 Span
logger.emit(...)独立 LogRecordOTLP Logs → Collector → Loki，在 Grafana Explore 查询
console.log(...)本项目的终端 stdout终端；它不会因为调用了 console API 就自动变成 OTel LogRecord

instrumentation.js 中的 traceExporter 发送 Span 及其 Events；logExporter 和 BatchLogRecordProcessor 发送 LogRecord。两条管道是分开的。

怎么选

  • 只对某个 Span 有意义的低频关键时刻：用 Event。
  • 需要严重级别、全文检索、长期保留或独立查询：用 LogRecord。
  • 异常要挂在失败 Span 上：用 recordException()，并另行 setStatus(ERROR)。
  • 不要默认同一个异常在多层重复记录，否则会产生噪声。

即时自测

recordException() 会创建新 Span 吗？

不会。它向现有 Span 的 events[] 添加 exception Event。

Event 与 LogRecord 都有时间戳，它们是同一个东西吗？

不是。Event 归属某个 Span；LogRecord 是独立 Logs 信号，只是可以通过 Trace ID / Span ID 关联。

为什么 recordException() 后还要 setStatus(ERROR)？

因为“记录异常细节”和“标记该 Span 执行失败”是两个独立动作。
