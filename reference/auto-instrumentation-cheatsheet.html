Node.js 自动插桩速查表

本质在模块加载或函数调用边界执行 patch/unpatch，不是旁路抓包。
加载顺序Instrumentation 必须早于被插桩模块；常用 --require / --import。
调用入口创建 CLIENT / SERVER Span，并通过 Context Manager 激活当前 Span。
跨进程客户端 inject traceparent；服务端 extract 后创建子 Span。
异步隔离Node.js 通常用 AsyncLocalStorage 保存每条异步调用链的 Context。
结束时机成功、错误、超时、取消都必须结束 Span，且只能结束一次。
自动 vs 手动自动插桩记录框架/依赖边界；手动 Span 补充业务语义，两者可以共存。
常见失败初始化太晚、模块版本不支持、重复 patch、Context Manager 缺失、Exporter 未刷新。

最小骨架

保存 original
→ 替换为 patched
→ startActiveSpan
→ inject(context.active(), headers)
→ 调用 original
→ response/error 时 span.end()
→ disable 时恢复 original
